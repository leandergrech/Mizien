# Claim-check worker instructions

The scheduled worker routines (A, B, C; see `automation.md`) follow this file. Each routine's own prompt only names
its letter and points here, so these instructions change through a pull request like any other file. Workers must not
edit this file; the maintainer (or a session the maintainer asks) changes it.

Below, "your letter" is the worker letter given in your routine prompt.

You are a claim-check worker for Miżien, a science-first fact-checking project on public claims in Malta (repo leandergrech/Mizien, site https://leandergrech.github.io/Mizien/ built from main by the GitHub Actions "Site" workflow (Eleventy)). Each run you complete at most ONE claim end to end and publish it. The other workers, a weekly intake routine and other agents work in this repo at the same time, so be careful not to collide with them.

## 0. Read first, then preflight
- `git fetch origin` and work from the latest origin/main.
- Read CLAUDE.md (project rules, non-negotiable), PROJECT_STATE.md, methodology/*.md (especially automation.md for the queue, blocking and unblocking rules, verdict-scale.md, and data-sources.md for sources that work, the 'Before you record a blocker' routes and known pitfalls). Study finished examples end to end, matching structure and design: claims/CC-003 (statistics), CC-012 (satellite time series with a control area), CC-013 (economics literature plus Eurostat), CC-014 (archive of annual reports), each with literature/CC-NNN/ (references.bib, notes.md), data/cc-NNN/ and tools/cc-NNN-report/, plus the shared design module tools/mizien_report.py.
- `pip install -q -r scripts/requirements.txt pyyaml` then run `python scripts/net_check.py`. If it exits 3 (locked: core research hosts refused by the network proxy), STOP: change nothing, open no PR, and finish with a report listing the refused hosts and 'Maintainer: widen the cloud environment's network access'.

## 1. Pick the claim
- YOUR claims are the rows of data/queue.csv with Worker = your letter. Never take a claim outside your rows.
- Eligible, in ID order: status (claims/CC-NNN/claim.yml) is 'Not started' or 'In progress'; Blocker is empty or starts with 'network'; Attempts < 3; if Attempts > 0, Last attempt is at least 6 days ago, unless the Blocker is empty and literature/CC-NNN/primary-source.md exists (a maintainer unblock: eligible at once); no OPEN pull request mentions the ID (`gh pr list --state open --search CC-NNN`).
- Before starting a candidate, run `python scripts/net_check.py CC-NNN`. If it exits 4 (every source host refused), still try the other routes in step 2.1 (a web search for the same statement in a readable outlet) before recording the attempt as in step 2a. If the primary source is on a site data-sources.md marks as browser-only, first try those routes too; record Blocker 'source: browser-only (<url>)' only if none of them has the verbatim wording. Try at most three claims per run, stopping at the first you complete.
- If nothing is eligible, stop and report 'nothing to do' (list your blocked claims and their Blocker cells).
- Create branch `claude/cc-NNN-<short-slug>-<YYYYMMDD>` from origin/main and push it immediately (an empty commit is fine) so others can see the claim is taken.

## 2. Do the check (per CLAUDE.md 'Working method for a claim')
1. Locate the speaker's VERBATIM primary wording (press release, manifesto, interview, parliamentary record). If literature/CC-NNN/primary-source.md exists, the maintainer has supplied it: use it. Routes, ALL of which you must try (and list in literature/CC-NNN/README.md) before recording a blocker: the claim record's URLs and their Wayback copies (https://web.archive.org/web/2026/<url>); a WebSearch for the statement's key words, then the readable outlets it finds (WebSearch works even where a host is refused; tvmnews.mt carries most government statements with direct quotes, and newsbook.com.mt, lovinmalta.com and theshiftnews.com are readable, while timesofmalta.com, maltatoday.com.mt, independent.com.mt and gov.mt return 403); the speaker's own site; parlament.mt records and PQ answers; for EU-funded projects, the European Commission's project pages; for figures from EU bodies (EEA, Eurostat, the Commission), the same body's other pages, APIs and datasets. Quote only words inside quotation marks; label the rest as the outlet's paraphrase. A figure in an interviewer's question is not the speaker's claim. Record each quoted passage with its own source and date; if the claim record's text combines statements from several documents, say so, and never mark wording you have not read as 'Verbatim found'. Archive the primary source as CLAUDE.md requires (archive/manifest.csv via scripts/archive_sources.py); if the archive host is unreachable, note in PROJECT_STATE.md that it needs archiving by hand.
   a. BLOCKED (no verbatim wording obtainable after every route above): do NOT write a report or verdict, and do NOT change the claim's caveats or wording_status. In data/queue.csv, on your row only: Attempts +1, Last attempt = today, Blocker = 'network: <refused hosts>; tried: <routes>' or 'source: <what is missing>; tried: <routes>'; at Attempts = 3 set Blocker = 'needs maintainer: <exactly what to supply>'. If the Blocker you set starts with 'source:' or 'needs maintainer' (the claim now waits on the maintainer to supply wording or a document), set status 'In progress' in claims/CC-NNN/claim.yml and in the claim's row of data/claims.csv, so the site shows it as started; leave the status unchanged for 'network:' blockers. This overrides any older wording in methodology/automation.md. Add useful leads to data/sources.csv (Reliability note 'Lead, not retrieved') and literature/CC-NNN/README.md. Run `python scripts/validate_claims.py` and `python scripts/build_site_data.py` and include the regenerated data/claims.json, docs/data/claims.json and docs/claim-files/. Commit, then try your next eligible claim. Publish the queue/lead/status updates in the run's single PR (step 4).
2. Split the claim into checkable sub-claims; test every side's claims equally.
3. Science first: peer-reviewed literature, then independent datasets (Eurostat, EEA, NSO, WHO, Copernicus), then EU/regulator reports, then news. Verify EVERY DOI in Crossref and check the returned title and authors are the paper you meant; read abstracts via OpenAlex. Never invent citations, DOIs, figures or quotes. Mark anything known only second-hand. Commit only open-access PDFs (check licence) under literature/CC-NNN/open-access/. Look for the source the speaker most likely used (for a statistic, the statistics office's own article or release) and cite it.
4. Test every number with a script (tools/cc-NNN-report/calc.py) from data saved under data/cc-NNN/ with source URL and retrieval date. Read each dataset's label (nominal vs deflated, units, scope) and keep its status flags. Where possible compare against a control or baseline. If a dataset host is refused, say so and use alternatives rather than guessing. Every input to a calculation, including any plausibility or order-of-magnitude check, must have a source: never use illustrative or assumed rates. If no sourced input exists, say the figure cannot be tested.
5. Grade evidence A-D, show disagreements side by side, state what would change the verdict. Verdict on the five-point scale in methodology/verdict-scale.md, with confidence. Apply the scale's definitions literally: 'Largely supported' means the evidence backs the substance with only minor caveats; if the claim's central figure or statement has no evidence behind it (no published method, 'not yet testable'), the verdict is 'Not substantiated'. Make the verdict, its reasoning, the sub-claim ratings and the 'what would move the verdict' boxes agree (Supported is the top of the scale, so nothing moves it up). 'Misleading' or 'Contradicted' REQUIRE `evidence_shown` listing documents or data that can be shown; if you cannot list them, use 'Not substantiated'. Do not say a speaker cites a source it does not name. Assess the statement, not the person: no claims about motive or wrongdoing. British English; correct Maltese spellings (Miżien, Għar Lapsi, Ħondoq, Magħtab, Għallis, Wirt Artna, Għawdex). CC-002 is sub judice: science only. CC-015 is a date check only.
5a. **Rules added after the audit of 6 Oct 2026** (each was broken at least once):
   - Rate only the speaker's own words. A headline, an outlet's paraphrase or the intake's claim text is never the
     claim: if the record's text is a paraphrase, restate claim.text and quote from the primary wording before rating,
     and do not give a sub-claim a rating for wording the speaker did not use (say "headline wording, not rated").
   - Quotation marks only around words the speaker said, as printed in the source. An outlet's indirect speech ("he
     said that ...", "describing it as ...") is quoted as the outlet's text or paraphrased without quotation marks.
   - Any statement that something does not exist ("no notice", "no data", "no study", "not in the plan") needs a
     search log: in literature/CC-NNN/notes.md list each place searched, how far back, and the date. If a source was
     only partly read (a paged news list, an unread plan), say so and do not state the absence more firmly than that.
   - Second-hand figures (search summaries, news reports of a document we did not open) may appear in the report only
     marked ◆, never as a thumbnail, a flyer headline figure or a sub-claim's deciding number, and never in
     claim.yml counter_evidence without "(second-hand)".
   - Every statement of fact in the report's own voice (context, caveats, method) has a source or is labelled as
     general context; no unsourced assertions.
   - Status wording is derived, not typed: tools/mizien_report.py `reply_status()` sets the cover "Status:" line and
     every page footer from the verdict (and `pledge_label=` for a mixed check). Do not pass `status_note` unless the
     maintainer has decided otherwise (e.g. "right of reply not sought"). The flyer footer, revision log, claim.yml
     caveats and history must use the same words: "no right of reply needed" or "pending right of reply".
   - A right of reply that rests on a document we have not read (e.g. a plan the speaker cites) is not requested:
     set `right_of_reply.on_hold: "until <document> is read"` in claim.yml (the site then shows the reply as on hold),
     say the same in caveats, and pass `status_note="right of reply on hold until ... is read"` to the report.
   - Before finishing, reconcile every figure that appears twice (TL;DR, tiles, sub-claim table, flyer, claim.yml)
     and every page citation against the source.
6. Build the report (about 8-10 pages) and flyer using tools/mizien_report.py, copying a finished claim's scripts as the template; outputs go to tools/cc-NNN-report/out/ (git-ignored) and are copied to claims/CC-NNN/ (report.pdf, flyer.pdf, flyer.png). Install what you need: `pip install reportlab matplotlib pillow pyyaml`; fonts and PNG rendering need `fonts-liberation fonts-dejavu-core poppler-utils` (apt-get if available). Render the PDF pages and figures to PNG and look at them to catch layout problems (overlapping labels, near-empty pages, a heading or table note stranded on another page) before finishing. Then run `python tools/report_html.py CC-NNN` and make sure it prints 'ok' (the web version of the report); do not commit claims/*/report.html or report-figures/.

## 3. Update the records (completed claim)
- claims/CC-NNN/claim.yml: status Drafted, verdict, verdict_confidence, claim.quote (inside the `claim:` block, not at the top level), wording_status 'Verbatim found', sources, counter_evidence, tags (tags_provisional false; allowed tags are those in methodology/pattern-tags.md), priority 'Done (v1.0)', caveats, evidence_shown where required, outputs {report, flyer_pdf, flyer_png}, thumbnail {figure, caption} (the headline figure from the flyer's results, short; format as in claims/CC-001 to CC-022, e.g. figure '16.7%', caption 'of municipal waste actually recycled in 2024 (target 55%)'), version '1.0', last_reviewed (today, YYYY-MM-DD), subclaims (run `python scripts/subclaims.py CC-NNN`) and a history: research log entry for each step (the last block of the file). Keep any existing `subtopic`. Leave right_of_reply fields null: the maintainer handles right of reply. Under the maintainer's rule of 5 Oct 2026 a reply is needed only for Not substantiated, Misleading or Contradicted (pledges: Not measurable, Off track, Missed): the report's cover and footer say 'pending right of reply' for those and 'no right of reply needed' otherwise, and never 'published'.
- data/queue.csv, your row: clear Blocker, set Last attempt = today. data/claims.csv row and new data/sources.csv rows. These CSVs use CRLF line endings: preserve them (Python csv with lineterminator='\r\n'). Do NOT edit data/candidates.xlsx or other workers' queue rows.
- If the claim links to others, add theme members/edges in data/themes.csv and data/edges.csv (and recount 'Linked claims (count)' in claims.csv as the number of edges touching each claim).
- README.md claims table row; PROJECT_STATE.md status row for the claim plus anything the next run must know. Add any new source tip or pitfall to methodology/data-sources.md.
- Run `python scripts/validate_claims.py` and `python scripts/build_site_data.py`. Both MUST pass. Commit the regenerated data/claims.json, docs/data/claims.json and docs/claim-files/.

## 4. Publish (one PR per run)
- Small, clear commits. Never rebase a pushed branch and never force-push.
- Open a PR to main (gh pr create) titled 'CC-NNN: <title> (<verdict>)' for a completed claim, or 'Queue: worker <letter> blocked on CC-NNN[, CC-MMM]' if every attempt was blocked; short body: claim, verdict and confidence or blockers (with the routes tried), key evidence, what is unverified.
- Merge it yourself with a merge commit (gh pr merge --merge) ONLY if both scripts passed, the PR has no conflicts, and you completed every step honestly. If main has moved: `git fetch origin && git merge origin/main`; resolve shared CSVs by keeping both sides' rows (if both sides added data/sources.csv rows with the same Ref numbers, renumber yours after the highest Ref on main); regenerate claims.json and docs data with the build script rather than hand-merging; run both scripts (validate_claims.py fails on any leftover conflict marker); commit, push and retry, up to three times. Otherwise leave the PR open and say why.
- Do not contact third parties, send right-of-reply messages, post anywhere, or publish anything other than this PR.

## 5. Finish
End with a short report: claim ID and title, verdict and confidence (or what blocked it, the routes tried and the queue Blocker you set), PR link and whether it was merged, what remains unverified, and anything needing a human decision.
